**你要做的事：**

把现有的 Python + JS + Java 三核心 Minecraft Bot Agent 系统，推倒重建为 TypeScript 单核心架构（TS Core）。根本动机有三个：旧架构 Python↔JS 桥接延迟高、进程模型臃肿、无法扛多用户并发。

**你要的系统形态：**

TS 直接通过 Mineflayer 跟 Java MC 服务器交互，发送命令立刻异步返回结果。中间用 BullMQ Worker 按消息队列串行处理任务，每一步执行进度通过 Socket.io 动态推送给前端。全链路异步，没有任何阻塞等待点卡住主循环。

**架构核心约束：**

1. **单写者原则** — 只有 BotActor 能碰 Bot，其他一切模块只能读、观察、请求，不能直接操作。
2. **API→Redis→Worker 三层解耦** — HTTP 请求进来只做校验和入队，立即 202 返回；Worker 异步消费；进度通过事件流推送。命令发出和结果返回彻底解耦。
3. **双轨 Worker** — BotWorker 只管执行游戏动作（躯干），BrainWorker 专门消化 LLM 调用、摘要压缩、向量化等高耗时任务（大脑），两者通过队列隔离，互不阻塞。
4. **JSONL 冷热分离** — 高频执行日志走本地 JSONL 追加写入，PG 只存摘要索引和文件指针，不拿关系型数据库当日志仓库。
5. **双轨 RAG** — MC 常识走 `minecraft-data` 确定性 API（零幻觉），历史记忆走 pgvector 混合检索（全文 + 向量）。
6. **TS 代码沙箱替代传统 MCP** — LLM 生成 TS 代码片段，通过受限 Facade API 在沙箱里执行，而不是用 JSON-RPC 声明式描述工具调用。

**Phase 1 边界：**

一主一 Bot，最小闭环。只做 goTo、mine、cutTree、collect、equip 这几个基础 skill。不做 craft/place/drop，不做多 Bot 多 Owner，不做复杂 replan 框架。旧系统只作参考库，禁止照搬 bridge 模式和旧的并发侵入模式。
