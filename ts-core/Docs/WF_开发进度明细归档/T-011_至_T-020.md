# 开发进度明细归档：T-011 至 T-020

> 本文件为 `WF_开发进度记录.md`（当前批次详细账本） 的批次归档。默认协作优先读取 `WF_任务阶段压缩记录.md`（阶段压缩记录）；只有追具体实现细节时再展开本文件。

## 批次概览

- 批次范围：`T-011` ~ `T-020`
- 阶段主题：外部输入统一、任务生命周期闭环、外部认证建模、本地启动 / 容器骨架、持久化边界、共享基础工具，以及 PostgreSQL（关系型数据库） / Redis（缓存） / BullMQ（任务队列） / Fastify（接口网关） / Mineflayer（Minecraft 协议客户端） 的真实 I/O（输入输出） 运行时骨架。
- 关键决策：从 `T-018` 起转为 MVP（最小可运行闭环） 关键路径优先，BrainWorker（摘要工作线程） 增强契约、部署文档补写、诊断占位等支线默认后移。

## 逐任务明细

### T-011（已完成）

- 目标：统一 `interfaces/game-chat`（接口层 / 游戏聊天） 与 `interfaces/server-bridge`（接口层 / 服务端桥接） 的入口契约。
- 审查要点：首轮因 `sender_id`（发送者标识） 与 `owner_id`（主人标识） 混用打回；修复后通过。
- 核心文件：`interfaces/contracts.ts`、`interfaces/game-chat/contracts.ts`、`interfaces/server-bridge/contracts.ts`、`__tests__/interfaces-ingress-model.spec.ts`。
- 结果：网页、游戏聊天、服务端桥接统一为标准消息包 / 事件包；服务端桥接固定 `runtime_effect: "observe_only"`（运行时影响：仅观测）。

### T-012（已完成）

- 目标：建立 `runtime`（运行时） / `workers`（工作线程） / `diagnostics`（诊断） 的任务生命周期事件闭环。
- 审查要点：首轮因终态默认伪造 `error`（错误） / `interrupt_source`（中断来源） 打回；修复后通过。
- 核心文件：`runtime/tasking.ts`、`runtime/events.ts`、`workers/contracts.ts`、`diagnostics/contracts.ts`、`__tests__/runtime-worker-event-model.spec.ts`。
- 结果：任务 accepted / started / discarded / terminal（已接受 / 已开始 / 已丢弃 / 终态） 全部有强类型动作和生命周期事件。

### T-013（已完成）

- 目标：集中修补外部认证契约、EasyAuth（离线服认证模组） 现实部署差异、日志保留配置和状态机语义。
- 审查要点：通过；清空 PostgreSQL（关系型数据库） 中旧 `authme`（旧认证模式） 假设。
- 核心文件：`runtime/contracts.ts`、`runtime/state-machine.ts`、`data/contracts.ts`、`db/contracts.ts`、`app/bootstrap.ts`。
- 结果：`INITIALIZING`（初始化） 成为默认启动态；`REFLEXING`（反射中） 中断改为 queue（排队）；EasyAuth（离线服认证模组） 作为外部认证源。

### T-014（已完成）

- 目标：补齐本地启动入口、启动摘要、Docker（容器） 骨架与运行说明。
- 审查要点：首轮因 `main` / `types`（入口元信息） 指向错误、运行镜像包含测试产物打回；修复后通过。
- 核心文件：`package.json`、`tsconfig.json`、`Dockerfile`、`.dockerignore`、`.env.example`、`src/main.ts`、`app/entrypoint.ts`。
- 结果：默认入口只输出 bootstrap-only（仅装配摘要），不自动连接 Redis（缓存） / PostgreSQL（关系型数据库） / Fastify（接口网关） / Mineflayer（Minecraft 协议客户端）。

### T-015（已完成）

- 目标：收口 `event_log`（事件日志） / `task_history`（任务历史） / `JSONL`（结构化日志） / `replay`（补拉） 纯持久化边界。
- 审查要点：首轮因 `sandbox_code`（沙箱代码） 日志引用被硬编码为 `tasks/*.jsonl` 打回；修复后通过。
- 核心文件：`data/contracts.ts`、`data/schema.ts`、`diagnostics/contracts.ts`、`interfaces/api.ts`、`interfaces/realtime.ts`。
- 结果：`skill_call`（技能调用） 对齐 `tasks/*.jsonl`，`sandbox_code`（沙箱代码） 对齐 `sandbox/*.jsonl` + `sandbox/*.code.ts`。

### T-016（已完成）

- 目标：补齐外部认证待执行到受控登录命令计划的最小执行骨架。
- 审查要点：首轮因长期状态暴露明文 `secret`（密钥） 打回；修复后通过。
- 核心文件：`runtime/contracts.ts`、`app/bootstrap.ts`、`__tests__/external-auth-execution-model.spec.ts`。
- 结果：明文密钥只存在于一次性执行动作载荷；公开状态、装配结果、接口快照均只暴露脱敏摘要。

### T-017（已完成）

- 目标：沉淀 `domain/invariants.ts`（领域不变量） 共享工具，并补记 `domain`（领域） 横切基础层定位。
- 审查要点：通过；没有把业务 shape（数据形状） 倒灌进 `domain`（领域）。
- 核心文件：`domain/invariants.ts`、`domain/index.ts`、`Docs/01_ARCHITECTURE.md` 及多处白名单调用点。
- 结果：共享 `assertNonEmptyString`（非空字符串断言） 与 `cloneReadonlyValue`（只读克隆） 替换散落重复实现。

### T-018（已完成）

- 目标：接入 PostgreSQL（关系型数据库） / Redis（缓存） 真实连接工厂和 Drizzle（数据库工具） migration（迁移） 入口。
- 审查要点：通过；资源创建、关闭与失败回滚均通过依赖注入测试。
- 核心文件：`db/connection.ts`、`db/migrations.ts`、`db/migrate.ts`、`drizzle.config.ts`、`app/bootstrap.ts`。
- 结果：PostgreSQL（关系型数据库） 基于 `pg.Pool`（连接池） + Drizzle（数据库工具），Redis（缓存） 基于 `ioredis`（Redis 客户端库） 且兼容 BullMQ（任务队列）。

### T-019（已完成）

- 目标：接入 BullMQ（任务队列） 三队列真实 `Queue`（队列） 与 Fastify（接口网关） 四路由骨架。
- 审查要点：首轮因跨 Bot（跨机器人） 请求和空白输入错误路径打回；修复后通过。
- 核心文件：`workers/bullmq.ts`、`interfaces/server.ts`、`app/bootstrap.ts`、`__tests__/workers-bullmq-model.spec.ts`、`__tests__/interfaces-server-model.spec.ts`。
- 结果：`/api/health`、`/api/status`、`/api/message`、`/api/replay` 可注入测试；服务关闭顺序为 `http -> workers -> redis -> postgres`。

### T-020（已完成）

- 目标：接入 Mineflayer（Minecraft 协议客户端） 传输工厂、observation（观测） 事件驱动缓存和 BotActor（机器人执行代理） 最小生命周期。
- 审查要点：首轮因公开可写 Bot（机器人） 句柄和连接失败清理缺口打回；修复后通过。
- 核心文件：`runtime/transport.ts`、`runtime/actor.ts`、`observation/runtime.ts`、`app/bootstrap.ts`、`__tests__/runtime-mineflayer-model.spec.ts`、`__tests__/observation-runtime-model.spec.ts`。
- 结果：传输只公开连接生命周期、快照和只读事件源；`INITIALIZING → IDLE`（初始化到空闲） 受 Mineflayer（Minecraft 协议客户端） 已连接和外部认证 ready gate（就绪门控） 双重约束；连接失败会清理监听器与 Bot（机器人） 句柄。
