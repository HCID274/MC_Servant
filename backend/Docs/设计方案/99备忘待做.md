  ### 2. 执行层：在真实世界里找最近那个方块

  真正找坐标的是 mineflayer_adapter.py。

  执行 mine("crafting_table") 时，走的是：

  1. _do_collect_block("crafting_table")
  2. 如果不是 any_log，就调用：
      - _find_block_by_name("crafting_table")
  3. _find_block_by_name(...) 会做这件事：

  - 先从 self._mcData.blocksByName["crafting_table"] 取到这个方块的 数值 ID
  - 再调 Mineflayer：
      - bot.findBlock({ matching: block_info.id, maxDistance: 32 })

  这一步的意思是：

  在 bot 周围 32 格内，扫描已加载世界，找最近一个 block id 等于 crafting_table 的方块。

  返回的是一个 Mineflayer Block 对象，里面就有：

  - name
  - position.x
  - position.y
  - position.z

  所以你问“它怎么知道工作台坐标的”，准确答案是：

  - minecraft-data 提供“工作台的标准方块 ID”
  - Mineflayer findBlock 根据这个 ID 在真实世界里找最近实例
  - 找到后得到它的真实坐标
  - 然后 collectBlock.collect(block) 负责走过去、挖掉、拾取

  

  
 五、这里还有一个你应该知道的边界
  现在“旁边这个工作台”这句话，执行层其实还没有真的理解“旁边”这个语义约束。

  因为 _find_block_by_name("crafting_table") 现在默认是：

  - maxDistance=32

  也就是说，它找的是32 格内最近的工作台，不一定是“紧挨着你的那个”。

  所以这次它能成功，不代表“旁边”这个语义已经被严格实现了。
  更准确地说，现在实现的是：

  “找到附近最近的工作台”，不是
  “严格限定你指的手边这个工作台”。

  这点如果你后面要做精细控制，需要单独加：

  - 视线目标
  - 鼠标指向
  - 更小半径
  - 或 Router/Planner 提供距离约束
